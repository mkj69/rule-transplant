Common setup

Models
A = Qwen3-0.6B-Base (base model). B = Qwen3-0.6B (chat model). Same architecture; B was trained further from A.
New rule
100 new operators generated with Opulse v1, built from substitution, conditional branches and bounded recursion, and calling each other. The random seed is private.
Training data
Only "expression = answer", no definitions or derivations. Expressions contain only new operators, integers 0–100 and brackets, e.g. Compute: 45 ♠₁₄₉ 57\nAnswer: 91.
A′
Full fine-tune of A on about 62k problems for 10 epochs, mixed with plain text so that A′ keeps its language ability. A′ scores 86.0 / 75.7 / 70.8% on the three held-out sets (single operator / composed / new numbers).
Rule evaluation
Three held-out sets the agent never sees: 970 single-operator, 917 composed, 497 new-number questions.
Ability evaluation
  • GSM8K, 500 problems: generated with the chat template, answer in \boxed{}, exact match.
  • IFEval, 329 prompts: generated, correct only if every format instruction is met.
  • MMLU, 500 questions: no generation; the option letter with the highest probability is the prediction. This measures knowledge and does not depend on output format.
Agent runs
One 24 GB GPU and at most 8 hours per run, inside a sandbox with no access to definitions, data, held-out sets or the Opulse code. The agent delivers an edited B′ and a method write-up.

Each setting in detail

Reference

A′ (ceiling)

A′ is trained directly on the rule data, so it shows the level that "knowing the rule" reaches. It is a base model and cannot chat, so its ability score is not used. Compare every other row's new-number accuracy with 70.8%.

Reference

B unchanged

B without any edit. 2.4% on new-number questions shows that B does not know the rule. Its ability score of 55.2 is the baseline for every "ability change".

Baseline: no agent

B + 0.25 · (A′ − A)

Multiply the weight difference A′ − A (the "task vector") by a coefficient and add it to B. This is the simplest weight-space method and needs no judgement.

We swept the coefficient from 0.05 to 1.5. A larger coefficient transfers more and damages more: at 0.5, new-number accuracy is 63.8% with an ability drop of 13.6; at 1.0, it is 71.2% with a drop of 36.9. The row shows 0.25, the best point with a drop of at most 2.

Conclusion: the task vector mixes the rule with a format change ("answer anything with a bare integer"). Almost all the damage is to chat format; knowledge is essentially unchanged.

Baseline: training

Distillation: train B on A′'s answers

Generate 62k random problems with the new symbols, let A′ answer them, and train B on the answers, mixed with B's own chat outputs and plain text and with a KL anchor to the original B.

B learns the rule (70.8%, same as A′) but loses 23.9 ability points, 35.1 of them in format. Note: this baseline uses the list of new symbols, which the agent does not get.

Reference: needs data

Train B on the training data

Train B on the same data as A′, with the same forgetting protection as distillation. The agent never sees the training data, so this row is a reference, not a competitor.

The result is close to distillation: 75.7% and an ability drop of 24.1. Learning the rule by training damages B's chat format.

Agent

Fable, no guidance (6 runs)

Fable gets the weights and architectures of A, A′ and B, and a one-sentence task: "A′ is A after it learned one new skill. Change B so that B also has this skill, and keep B's original abilities." Two rules, 3 runs each: "weights only" (B must not be trained on A′ outputs) and "may query A′".

All 6 runs fail: 0.2–19.1% on new-number questions, mean 9.7%. Ability is preserved in all of them.

Reason: no run found the new operator symbols. The agents only saw the output-side change and guessed the skill as "answer with one integer" or "answer briefly". The best runs match B + a small multiple of the task vector. One run equals a fixed formula that needs no agent.

Agent

Fable, given symbol list and dependency order (7 runs, 6 valid)

As above, plus one file: the 100 new symbols, how each is written (e.g. a ♡₂ b), and which other new symbols each one uses, in dependency order. What each symbol computes is not given. The task asks for transfer one operator at a time in that order, with a check after each.

4 of 6 valid runs succeed: weights-only W/1 and W/2, may-query Q/2 and Q/3. The four successful runs reach 45.3–63.2% on new-number questions with ability changes from −1.8 to +1.1.

Two runs fail. W/3 reaches 71.4%, as high as A′, but loses 9.4 ability points. Q/4 reaches 46.9%, above the line, but loses 3.3 ability points.

Per run (new-number accuracy / ability change): W/1 63.2% / −0.5, W/2 58.0% / +1.1, W/3 71.4% / −9.4, Q/2 58.2% / −1.8, Q/3 45.3% / −0.1, Q/4 46.9% / −3.3. May-query run 1 ended after 1.5 hours before its planned training started and is not counted.

The successful weights-only method filters the task vector before adding it to B. In each layer it keeps only the input directions that are active on operator prompts and quiet on B's everyday tasks. Embedding rows change only for the tokens of the new symbols. The weights-only runs delivered a single merge of all 100 operators. One of them also tried strict one-by-one transfer, with almost the same result (68.3% vs 69.1% agreement with A′).

The may-query runs did not use the task vector. They let A′ answer problems and trained B on those answers (distillation), with an extra term that keeps B′ close to the original B on B's own everyday answers. Q/2 added operators in 4 cumulative stages (1–25, 1–50, 1–75, 1–100). Q/3 used 10 stages in list order, then a final pass over all operators with a strong anchor. Q/4 trained all 100 at once with LoRA and scaled the resulting change by 0.7.

Agent

Astra, definitions one at a time, no training (1 run, stopped at operator 19)

This setting gives no A or A′, only B and the definition of each operator. A tool reveals one definition at a time; the agent gets the next one only after finishing the current one. Gradient training is not allowed; only direct weight edits, such as hand-compiled circuits written into B or closed-form edits like ROME/MEMIT. Snapshots of B′ after 5, 10, 20, 40, 70 and 100 operators give a curve of how many operators can be added.

It answers: when the answer is known, how many operators can be added by editing weights directly? The model is gpt-6-astra at its highest reasoning level (ultra), not the Fable model used above.

Result: one run only. It stopped at operator 19 when the Codex quota ran out. Saved snapshots (new-number accuracy / operators learned / ability change): after 5, 14.9% / 3 / −0.3; after 10, 15.7% / 5 / −0.3; after 14, 18.3% / 8 / −2.5; at the stop (19), 21.3% / 10 / −3.7. New-number accuracy is above unchanged B (2.4%), but from operator 14 on the ability drop exceeds 2 points. By the success line this run fails. It is a single run that never received all 100 definitions, so it supports no conclusion.

What this shows

1. Without an agent, learning the rule and keeping abilities trade off

Adding the task vector: coefficient 0.25 transfers only 20.5%; coefficient 1.0 transfers 71.2% but costs 36.9 ability points. Training methods (distillation, direct training) reach 71–76% but cost about 24 points. No standard method gets both.

The task vector carries two things: the rule, and a format change ("answer any question with a bare integer") that comes from training data with only one format, problem → integer. The damage is almost all format: at coefficient 1.0 format drops 53.4 and knowledge only 3.8.

2. The bottleneck is identifying the skill, not moving it

Same model (Fable), same budget, same weights; the only addition is a symbol list. Success goes from 0 / 6 to 4 / 6, and mean new-number accuracy from 9.7% to 57.1%.

Without guidance no run found the new symbols. The agents looked at A′'s outputs, saw "A′ always answers with an integer", and treated the skill as an answer format. The symbols could have been found from the input side, for example the tokens whose embeddings changed most between A and A′, but no run followed that lead.

So what stops the agent is finding out what was learned from the weight difference. Once it knows what to move, it can move it.

3. With guidance, the agent beats every baseline on both axes

At an ability change near zero, adding the task vector reaches at most about 11–20% (coefficient 0.2–0.25). The four successful guided runs reach 45.3–63.2%, 2–6 times more.

Against the training baselines, the guided agent transfers less (mean 57.1% vs 70.8–75.7%), but the successful runs keep abilities almost unchanged, where the training baselines cost about 24 points.

The two rules must be read separately. Weights-only W/1 and W/2 do not train; they only compute weights. May-query Q/2 and Q/3 also train (distillation), but with a better forgetting guard (stay close to the original B on B's own answers), and lose only 1.8 and 0.1 points. So the 24-point loss of the training baselines comes mainly from our forgetting recipe, not from training as such.

4. Rule and format separate by where they are active, not by magnitude

A control: removing the 64 largest directions of each matrix of the task vector before adding it to B preserves abilities but also removes almost all of the rule (new-number accuracy 70.4% → 14.7%). Rule and format share the largest directions, so a magnitude cut cannot separate them.

The successful method uses another criterion: keep the directions that are active on operator prompts and quiet on B's everyday tasks. This separates the two. Rule and format share large directions but are driven by different inputs.

5. How much to transfer versus keep is a point the agent chooses

Guided W/3 reaches 71.4%, as high as A′, but loses 9.4 ability points (GSM8K 61.6 → 30.0). Q/4 stops near the line: 46.9% with a loss of 3.3 points. The four successful runs chose more conservative points. With guidance the outcome is a curve that lies above the baselines, and agents land at different points on it.

6. Transferring strictly one by one gave no clear benefit

The only strictly sequential transfer matched the single merge from the same run (68.3% vs 69.1% agreement with A′). Knowing which symbols to move matters; the order does not seem to. This is a single comparison.

7. Operators that do not transfer are mostly ones A′ never really learned

The agents scored all 100 operators. Those with low agreement are mostly ones that A′ itself answers inconsistently, as if memorised. B′ is therefore limited by A′: A′ reaches 70.8% on new-number questions, and the successful runs' 45–63% is 64–89% of that.

What this experiment can and cannot claim

Well supported

1. The weight change left by training is not a clean "skill package"

A′ − A contains the new rule and a side effect, "answer any question with a bare integer", which comes from training data with only one format, problem → integer. Added to another model, the rule and the side effect move together, so the more B learns, the more of its chat ability it loses. A full coefficient sweep supports this at all three sizes (100, 1,000 and 10,000 operators).

2. For current agents, the hard part is identifying what was learned, not moving it

Same model, same budget, same weights; adding only a symbol list changes success from 0 / 6 to 4 / 6 and mean new-number accuracy from 9.7% to 57.1%. Without the list the agent watched A′'s outputs, saw the side effect ("always answers with an integer") and took the side effect for the skill. The two settings differ in one variable only; this is the cleanest and most valuable comparison in the study.

Interesting, needs more evidence

3. Rule and side effect differ in which inputs activate them, not in magnitude

A magnitude cut (dropping the 64 largest directions of the task vector) removes rule and side effect together (new-number accuracy 70.4% → 14.7%). An activation cut (keeping directions active on operator prompts and quiet on everyday tasks) keeps the rule and mostly removes the side effect. If this holds, model merging and task-vector methods should select weights by the inputs they act on, not by the weights alone. Limitation: the agent found this method; we have not yet verified it with a fixed script that needs no agent.

4. Once the target is known, weight editing alone gets results close to good training

Weights-only guided runs (W/1, W/2) reach 58–63% with almost no ability loss and no training. May-query guided runs (Q/2, Q/3) train with a better forgetting guard, reach 45–58%, and also lose only 1.8 and 0.1 points. The training baselines reach 71–76% but lose about 24, mainly because of our forgetting recipe. So we cannot say that weight editing is the better trade than training. We can say that both routes move most of the rule with almost no ability loss.

What we cannot claim yet
  • Not that "agents can read weights". In the successful runs we did the "identify the skill" step for them.
  • Not cross-architecture transfer. The 4 cross-architecture runs had no guidance and all failed; the question is still open.
  • No generalisation to other rules or larger models. There is one synthetic rule set, one pair of 0.6B models and 6 valid guided runs at 100 operators.
  • The agent was constrained. The API gateway cut any single response longer than about 2 minutes, which may underestimate the agent.
  • Whether one-by-one transfer helps is unclear. Most runs did not actually transfer one by one; the only strictly sequential run matched a single merge.
Insight

Identifying what was learned from a weight difference is an underrated step in self-improvement

A common picture of self-improving systems is that a new model reads the old model's changes and moves them over. This experiment pins down where that breaks: not in moving, but in finding out what was learned.

A clue: the new symbols are easy to find from the input side, for example the tokens whose embeddings changed most between A and A′. None of the 14 unguided runs looked there. Current agents look for behaviour changes in outputs and rarely ask which inputs are new. That may be a skill that can be trained or prompted.

Most useful next steps
  1. Weak hint: say only that the skill involves some new tokens, without the list, and see whether the agent finds the symbols itself. This is the key test of claim 2.
  2. Turn the successful filtering method into a fixed script and run it without an agent. If it works, claim 3 moves from "the agent happened to find it" to "the method works". Only GPU time is needed.
  3. Give guidance in the cross-architecture setting to actually test cross-architecture transfer.

Limitations to state with the table

  • The guided setting has only 6 valid runs (3 weights-only, 3 may-query); "4 / 6" rests on a small sample.
  • The definitions arm has one run, which stopped at operator 19 when the quota ran out; it does not show what happens with all 100 definitions.
  • The symbol list does the "identify the skill" step for the agent. This row shows that an agent can transfer a skill it has been told about, not that it can identify the skill itself.
  • All Fable runs went through an API gateway that cuts any single response longer than about 2 minutes. The conclusions hold under that limit.
  • Each ability test has 329–500 items, so scores vary by an estimated 2–3 points (not measured). A result like −1.8, close to the line, is not a stable pass.
  • Larger rules (1,000 and 10,000 operators) and B models of other architectures were tested without guidance. All failed, so they are not in this table.
